# Git
1. 실질적인 내용 변경이 없는 파일은 git에 커밋하지 않는다. (공백·줄바꿈·trailing space만 바뀌었거나 재생성으로 내용이 동일한 경우, 스테이징에서 제외하고 `git checkout`으로 되돌린다.)
2. 파일 이동은 모두 `git mv`로 처리한다.
3. 과거 커밋을 수정할 때 원래 커밋 날짜와 시간을 유지한다.
   1. cherry-pick이나 rebase 시 `--committer-date-is-author-date` 옵션을 사용한다.
4. 다른 성격(예: fix, docs, feat)의 변경은 하나로 묶지 않고 각각 커밋한다.
5. 커밋 메시지는 `[prefix] 내용` 형식으로 작성한다.
   1. 제목은 변경 사항을 상세하게 작성한다.
   2. 내용이 많으면 본문에 `-` 불릿으로 추가한다.
   3. 추상적이거나 동일한 메시지를 반복하지 않는다.
6. 커밋 메시지가 사용자와 논의된 경우, 별도 확인 없이 바로 push까지 이어서 실행한다.
